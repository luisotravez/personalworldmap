# Contributing

This guide was started by Luis Carranza Perales (@luisotravez), who maintains the master. It has one master version on the `main` branch. You can make your own version (fork) and you can propose improvements to the master.

## Make your own version

Fork this repository, or use it as a template, and change anything you like. The license asks you to credit this project and share your version under the same terms.

## Propose an improvement

Open an issue with the proposal form. A good proposal answers three questions:

1. **What changes?** The file, the day, the sentence or the source.
2. **Why?** What problem does it solve, and for whom?
3. **What supports it?** A public source, or your own experience using the guide.

You can also open a pull request. Please describe it with the same three questions.

## What fits

Before proposing, check the questions in the README: which task it serves, whether it teaches a reusable method, whether it is public and referenced, and whether it helps someone publish.

## Suggest a source

Use the source suggestion form. Include the link, what it teaches, which day it could serve, and whether it is a base source, a counterpoint or an example of how the idea is evolving. Please paraphrase. Do not paste paid material.

## If we reference you

If you are a creator mentioned in [sources.md](sources.md) and want something corrected or removed, open an issue and we will act on it.

## Review

Proposals are reviewed at a regular rhythm. Accepted changes are recorded in [CHANGELOG.md](CHANGELOG.md) with the reason. Declined proposals get a short explanation.
